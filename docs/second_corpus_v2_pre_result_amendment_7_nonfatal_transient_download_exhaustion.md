# C2 V2 pre-result amendment 7: nonfatal exhausted transient distribution downloads

**Date:** 2026-10-17  
**Applies to:** C2 corpus construction only  
**Scientific protocol:** unchanged (`SECOND_CORPUS_DATAEUROPA_V2`)  
**Transport revision:** V2.4  
**Observed retrieval/generation results before amendment:** none  
**Final C2 corpus freeze before amendment:** none

## Trigger

During the provisional V2.3 corpus-construction run, after 7 ECON datasets had been provisionally accepted, a distribution hosted on an ArcGIS endpoint returned HTTP 500 for all three frozen download attempts. The V2.2 deterministic core then raised a fatal `RuntimeError` and stopped the entire corpus build.

No `corpus_freeze.json` had been produced, no C2 query set had been authored, and no retrieval or generation experiment had been run.

## Why this is an implementation defect

The frozen protocol already states that a failed or ineligible distribution is skipped and that the next distribution in deterministic frozen order is tried. Therefore, exhausting bounded retries for one transiently unavailable distribution must be represented as distribution-level attrition, not as a fatal corpus-level error.

V2.4 changes only that transport behavior. It does not alter candidate ordering, publisher caps, licence eligibility, download-URL requirements, format eligibility, the 5 MiB payload limit, extraction rules, the 512-chunk limit, the requirement for two eligible distributions, or the 200-dataset target per theme.

## Frozen V2.4 behavior

For each distribution:

1. The same maximum of three download attempts is retained.
2. HTTP 429/500/502/503/504 and request exceptions remain transient retry conditions.
3. Retry waits remain 2 s and 4 s before attempts 2 and 3.
4. If all attempts fail transiently, the distribution is recorded with reason `transient_retry_exhausted:<last_error>`.
5. Selection then proceeds to the next distribution in the already-frozen deterministic order.
6. Non-transient failures continue to be recorded immediately as distribution attrition.

This matches the pre-existing failed-distribution rule in the frozen protocol.

## Restart policy

The aborted V2.3 run is provisional and superseded before corpus freeze. V2.4 restarts deterministic selection from rank 0. The frozen candidate universe, candidate order, and cached metadata-detail snapshots remain unchanged. Partial selected/raw/canonical-text/chunk artifacts from the aborted run are regenerated by the selector before a new corpus freeze is produced.

## Scientific status

This amendment is a transport/error-handling correction discovered during pre-query corpus construction. It is not based on retrieval quality, provenance churn, answer drift, H1/H2/H3 outcomes, or any other C2 scientific result.
